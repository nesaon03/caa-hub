WHAT CHANGED
------------
Hub now loads from Junkie's protected CDN first, GitHub second.

  1. Junkie CDN   <- obfuscated, key checked server-side  (preferred)
  2. GitHub raw   <- fallback if delivery is unreachable
  3. local file   <- fallback if GitHub is unreachable

The key gate is still ours (WindUI window, same look, same behaviour).
The difference: once a key passes, it is handed to Junkie's delivery API,
which returns a signed CDN url for the obfuscated script. The protected
payload is never served to anyone the server has not accepted, so the
gate is no longer skippable by reading a public file.

Deliberately NOT used: the loader Junkie generates for you at
https://jnkie.com/loaders/onxy-hub - it exits before checking a key
(its game map is keyed by place id but read with universe id, so it
always warns "Unsupported game [LDR-NOMAP]"). See
skills/.../windui-luau-hubs/references/jnkie-loader-contract.md

WHAT TO DO WITH IT
------------------
Nothing. It is pushed and live. Users run the one-liner above.

To test the accept path yourself: get a key from the flow page, paste it
into the window, and the hub should load. If it says "Key not found" the
key is wrong/expired; if it says "delivery unavailable" in the console,
the CDN rejected the key but GitHub carried the load anyway.
